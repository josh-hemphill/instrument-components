# 0.3.0-alpha.1 release qualification

This coordinated prerelease spans the SDK, facade, VISA, managed OpenTAP and all five external driver repositories. Availability is established by matching registry versions and seven GitHub releases, not by this preparation document.

Use exact 0.3.0-alpha.1 Rust/NuGet pins and instrument-driver-tools 0.3.0a1. The 34401A registration is intentionally incompatible: use an explicit commissioned QualifiedScpi factory. See [getting started](../getting-started.md). No production compatibility promise or hardware validation is implied.

Publication order: SDK tag `driver-sdk-v0.3.0-alpha.1`, root `v0.3.0-alpha.1`, Keithley/Rigol/Siglent/Tektronix `driver-v0.3.0-alpha.1`, then Keysight last for the all-five public gate. Dependencies must be available before their dependents publish.

Each publisher retains its original archive and an identity record. A retry compares the public archive to those source-bound bytes. For NuGet only, the registry signature and ZIP container metadata are excluded from canonical payload comparison; all named payload bytes must match. Identity disagreement stops publication. Never move a tag, overwrite a package, or blindly skip duplicates. Use a new version for a changed payload. Root retry source refs must resolve to the exact tag commit. Retain partial-publication job artifacts before retrying.

The OpenTAP TapPackage requires managed package verification, install/uninstall/reinstall and mock lifecycle checks; it is not Native AOT. Software results do not establish calibration, timing, protection, electrical suitability, or device behavior on a physical bench. All hardwareValidated fields remain false.

## Resume a partial publication

Keep the tag and its commit unchanged. Download the failed attempt's `publication-crates` / `publication-nuget` artifacts before rerunning; those contain original archives and source-bound JSON records, including failed stages. A normal job rerun rebuilds and compares against the registry, stopping on different payload bytes. It never assumes a duplicate is equivalent. For a qualified manual NuGet replay from the exact tag checkout, retain the original record beside its archive and run:

```sh
python tools/release-package.py --nuget /retained/InstrumentComponents.Runtime.0.3.0-alpha.1.nupkg --replay-record /retained/InstrumentComponents.Runtime.json --output /tmp/replay-proof
```

Use the workflow's authenticated publisher environment for this command; do not paste or store API keys in scripts or logs. For Rust, `--crate instrument-runtime --replay-record /retained/instrument-runtime.json` additionally requires the rebuilt archive to equal the retained original; compiler/dependency/source differences stop the replay. A changed Rust payload requires a separately reviewed new version. No original is downloaded automatically by a fresh job. GitHub asset retries compare existing bytes and stop on mismatch; never remove an existing asset to make a retry pass.

### Recover qualification or assets after registry publication

The release dispatch workflow provides two mutually exclusive recovery inputs. Select a reviewed helper ref while retaining the original published tag, full payload commit and producer run. The ordinary registry publishers are skipped in these modes.

For an SDK asset failure, use `recover_sdk_assets_from_run` with the SDK tag. The job requires the original SDK qualifications and both registry publishers to have succeeded, then verifies and uploads the original wheel and checksum file. For root public-consumer or asset failures, use:

```sh
gh workflow run release.yml --ref REVIEWED_HELPER_REF -f tag=v0.3.0-alpha.1 -f source_ref=FULL_TAG_COMMIT -f recover_root_from_run=ORIGINAL_RUN_ID
```

Root recovery requires the original qualification, registry and TapPackage jobs to have succeeded. Four fresh Windows/Linux x64 .NET 8/10 consumers run against the public registries using the original payload checkout and SDK artifacts. Local reference packages are rebuilt for qualification bookkeeping; they are labeled reference-only and are never published. The TapPackage job waits for all four public proofs and uploads only the original retained TapPackage, then downloads it for byte comparison.

Receipts distinguish the published payload commit from the corrected helper/workflow commit and preserve the original failed run. Retain the recovery artifacts and independently verify the released assets and installed consumers. A successful recovery does not change the original job's status or provide physical hardware evidence.
