# Rust / C# parity in the 0.2 preview

The generated catalog has eight classes and83 operations, shared validation domains, replies, physical units and statuses. Both languages support direct sync, native async, dedicated-worker async callers and blocking worker callers. Static factories and passive evidence matching use the same rank/tie rules. One shared backend owns class configuration and lifecycle.

Parity evidence includes shared positive/invalid profile fixtures, optional-argument plans, unknown/known temperature units, immutable model/endpoint inventories, complete-output shutdown attempts, malformed replies, cancellation/recovery, transport faults, disposal and thread affinity. The external packages add source-derived independent wire/value/error cases for every migrated operation. C# generated and packed consumers execute as actual Native AOT binaries on Windows/Linux x64 with.NET8/10. Rust default/async consumers use versioned archives.

Source, package bootstrap, public-registry consumers and physical evidence are separate layers. The current evidence index records exact revisions/run IDs/artifact hashes. Public previews and hardware validation remain pending until their respective gates actually run. No old API compatibility is required. See [the architecture](device-driver-sdk.md), [delivery](device-package-delivery.md) and `spec/device-extraction-index.json`.
